## Мультитенантность (Multi-Tenancy)
-   ```Database Multi-Tenancy (Отдельная база данных на каждого арендатора)``` (максимальный уровень изоляции клиентов) - данные разных организаций хранятся в изолированных СУБД; высочайшая безопасность
-   ```Schema Multi-Tenancy (Отдельная схема БД на каждого арендатора)``` (баланс между изоляцией и расходом ресурсов серверов) - одна БД, разные схемы (`tenant_a.users`, `tenant_b.users`); миграции накатываются на каждую схему
-   ```Discriminator / Row-level Multi-Tenancy (Разделение по колонке tenant_id в таблицах)``` (минимальные затраты инфраструктуры при высокой плотности клиентов) - все клиенты в одной таблице; разделение через автоматический фильтр `@TenantId` (Hibernate 6)
-   ```@TenantId (Hibernate 6 нативная аннотация)``` (автоматическая привязка и фильтрация строк по тенанту) - Hibernate автоматически добавляет `tenant_id` в INSERT и `WHERE tenant_id = ?` во все SELECT
-   ```MultiTenantConnectionProvider``` (интерфейс поставщика соединений под конкретного арендатора) - переключает соединение или `schema` в JDBC соединении в зависимости от переданного `tenantIdentifier`
-   ```CurrentTenantIdentifierResolver``` (определение текущего тенанта из контекста безопасности или заголовка запроса) - извлекает Tenant ID из `SecurityContext`, JWT токена или HTTP заголовка `X-Tenant-ID`
