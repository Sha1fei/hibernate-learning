## Жизненный цикл сущности
-   ```Transient``` (новый объект, не связанный с Session и не имеющий записи в БД) - создан через `new`; Hibernate о нём не знает; не имеет ID (или ID не из БД)
-   ```Persistent / Managed``` (объект привязан к Session и отслеживается Hibernate) - изменения автоматически синхронизируются с БД при `flush()`; находится в кэше первого уровня
-   ```Detached``` (объект был persistent, но Session закрыта или объект отсоединён) - имеет ID из БД, но изменения не отслеживаются; `merge()` — вернуть в managed состояние
-   ```Removed``` (объект помечен на удаление, будет удалён из БД при flush) - `session.remove(entity)` или `em.remove(entity)`; объект ещё существует в памяти до коммита
-   ```persist(entity)``` (перевод transient-объекта в persistent и планирование INSERT) - JPA метод; не возвращает значение; объект становится managed; ID генерируется (зависит от стратегии)
-   ```merge(entity)``` (копирование состояния detached-объекта в persistent контекст) - возвращает managed копию; оригинал остаётся detached; если сущности нет в БД — делает INSERT
-   ```save(entity)``` (Hibernate-метод сохранения, возвращающий сгенерированный ID) - deprecated в Hibernate 6; аналог `persist()`, но возвращает `Serializable` ID
-   ```flush()``` (принудительная синхронизация persistence context с БД) - выполняет INSERT/UPDATE/DELETE запросы; не делает коммит; Hibernate вызывает автоматически перед запросами и коммитом
-   ```clear()``` (полная очистка persistence context, все объекты становятся detached) - освобождает память; полезно при batch-обработке больших объёмов данных
-   ```refresh(entity)``` (перезагрузка состояния сущности из БД, отменяя несохранённые изменения) - перезаписывает поля объекта актуальными значениями из БД
-   ```detach(entity)``` (отсоединение конкретной сущности от persistence context) - объект перестаёт отслеживаться; изменения не будут синхронизированы с БД
-   ```Dirty Checking``` (автоматическое отслеживание изменений managed-сущностей) - Hibernate сравнивает текущее состояние с snapshot при загрузке; при `flush()` генерирует UPDATE только для изменённых полей
