## Жизненный цикл и FlushMode
-   ```Transient State``` (состояние нового объекта, созданного через оператор new) - не имеет записи в БД, не привязан к сессии; изменение его полей не отслеживается
-   ```Managed (Persistent) State``` (объект привязан к сессии и отслеживается Persistence Context) - все изменения свойств автоматически сохраняются в БД при следующем сбросе буфера (`flush()`)
-   ```Detached State``` (объект имеет ID из базы, но сессия, в которой он был загружен, уже закрыта) - изменения не отслеживаются; при обращении к неинициализированным LAZY-полям бросает `LazyInitializationException`
-   ```Removed State``` (сущность помечена на удаление через session.remove() / em.remove()) - при сбросе буфера сессии для неё будет выполнен SQL-запрос `DELETE`
-   ```Dirty Checking (Механизм грязной проверки)``` (автоматическое определение изменённых свойств перед flush) - Hibernate хранит теневую копию (snapshot) каждого объекта и при flush сравнивает каждое поле
-   ```session.flush()``` (принудительная синхронизация состояния объектов в памяти с базой данных) - выполняет накопленные SQL-запросы в JDBC соединении; транзакция при этом НЕ коммитится
-   ```FlushModeType.AUTO``` (режим сброса по умолчанию) - сессия автоматически выполняет `flush()` перед выполнением любого HQL/JPQL запроса, если запрошенные таблицы были изменены в памяти
-   ```FlushModeType.COMMIT``` (откладывание flush до момента явного завершения транзакции) - оптимизация, исключающая промежуточные `flush()` перед запросами чтения; требует осторожности во избежание фантомов
-   ```session.merge(detachedEntity)``` (возврат отсоединённого объекта обратно в persistent контекст) - копирует поля переданного объекта в актуальный managed-экземпляр и возвращает его; оригинал остаётся detached
-   ```session.clear() & session.evict(entity)``` (очистка кэша первого уровня сессии) - `clear()` отсоединяет вообще все объекты, освобождая оперативную память при пакетной обработке
-   ```session.refresh(entity)``` (принудительная перезагрузка состояния сущности из БД) - отменяет все незакоммиченные локальные изменения объекта в памяти, восстанавливая актуальные значения из строки таблицы
