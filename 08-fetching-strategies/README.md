## Стратегии загрузки
-   ```FetchType.LAZY``` (загрузка связанных данных только при первом обращении к ним) - по умолчанию для `@OneToMany`, `@ManyToMany`; возвращает прокси; доступ вне Session → `LazyInitializationException`
-   ```FetchType.EAGER``` (загрузка связанных данных сразу вместе с родительской сущностью) - по умолчанию для `@ManyToOne`, `@OneToOne`; удобно, но опасно для производительности на больших графах
-   ```N+1 проблема``` (ситуация когда загрузка N сущностей порождает N дополнительных запросов) - пример: загрузка 100 пользователей + 100 запросов за заказами каждого; решение: `JOIN FETCH`, `@BatchSize`, `@EntityGraph`
-   ```JOIN FETCH``` (загрузка связей одним SQL JOIN запросом вместо отдельных) - `SELECT u FROM User u JOIN FETCH u.orders`; решает N+1; нельзя использовать с пагинацией (Hibernate загрузит всё в память)
-   ```@BatchSize(size = 25)``` (загрузка LAZY-коллекций пакетами вместо по одной) - Hibernate загружает коллекции для 25 родителей за раз; `WHERE user_id IN (?, ?, ..., ?)`; значительно снижает количество запросов
-   ```@EntityGraph(attributePaths = {"orders", "orders.items"})``` (декларативное указание какие связи загружать в конкретном запросе) - переопределяет `FetchType` для конкретного запроса; не меняет маппинг сущности
-   ```@Fetch(FetchMode.SUBSELECT)``` (загрузка всех LAZY-коллекций одним подзапросом) - Hibernate выполняет `WHERE user_id IN (SELECT id FROM users WHERE ...)`; один дополнительный запрос вместо N
-   ```@Fetch(FetchMode.JOIN)``` (Hibernate-специфичный способ принудительного JOIN для связи) - аналог EAGER через JOIN; применяется всегда, в отличие от `JOIN FETCH` который указывается в запросе
-   ```Hibernate.initialize(user.getOrders())``` (принудительная инициализация LAZY-прокси внутри открытой Session) - вызывает загрузку данных; полезно перед отправкой сущности за пределы транзакции
-   ```LazyInitializationException``` (ошибка доступа к LAZY-данным после закрытия Session) - решения: `JOIN FETCH`, `@EntityGraph`, `@Transactional` на сервисном слое, DTO-проекции
