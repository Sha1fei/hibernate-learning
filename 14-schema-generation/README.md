## Генерация схемы и миграции
-   ```hibernate.hbm2ddl.auto (Режимы управления схемой)``` (поведение Hibernate по отношению к таблицам БД при старте) - `validate` (только проверка соответствия схеме — стандарт для prod); `update` (добавление колонок/таблиц — только dev); `create-drop` (для тестов); `none`
-   ```Связка с Flyway / Liquibase``` (золотой стандарт версионирования в продакшене) - миграции выполняются через инструмент версионирования, а Hibernate настраивается в режим `hbm2ddl.auto=validate`
-   ```@Index & @Table(indexes = ...)``` (декларативное описание индексов в метаданных сущности) - Hibernate генерирует `CREATE INDEX` в схеме; поддерживает составные индексы и уникальные ограничения
-   ```@UniqueConstraint``` (декларация составного уникального ограничения на уровне таблицы) - гарантирует уникальность комбинации полей (например `organization_id` + `code`)
-   ```jakarta.persistence.schema-generation.scripts.action=create``` (экспорт DDL скрипта генерации в файл без обращения к БД) - полезно для генерации начального скрипта `V1__init.sql` для Flyway прямо по классам `@Entity`
-   ```Naming Conventions (Соглашения об именовании в DDL)``` (автоматическое форматирование имен внешних ключей и индексов) - предотвращение конфликта длинных имен ограничений в Oracle и PostgreSQL
