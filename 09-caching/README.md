## Кэширование (L1, L2, Query Cache)
-   ```Кэш первого уровня (L1 / Session Cache)``` (встроенный кэш сессии, включенный всегда) - сохраняет идентичность сущностей по первичному ключу (`a == b`); предотвращает повторные запросы за одним и тем же ID внутри одной транзакции
-   ```Кэш второго уровня (L2 / Shared Cache)``` (разделяемый между всеми сессиями распределённый кэш на уровне SessionFactory) - хранит дегидрированные данные (массивы значений колонок) по ID сущности; требует провайдера (Ehcache, Caffeine, Redis)
-   ```@Cacheable & @Cache(usage = ...)``` (пометка сущности или коллекции как кэшируемой в L2) - стратегии concurrency: `READ_ONLY`, `NONSTRICT_READ_WRITE`, `READ_WRITE`, `TRANSACTIONAL`
-   ```CacheConcurrencyStrategy.READ_WRITE``` (стратегия кэширования с защитой от чтения «грязных» данных через soft-lock) - при обновлении строки блокирует кэш-запись до коммита транзакции
-   ```Query Cache (Кэш результатов запросов)``` (кэширование списков идентификаторов, возвращенных HQL запросом) - `hibernate.cache.use_query_cache=true`; работает ТОЛЬКО в связке с L2 кэшем; сбрасывается при любом изменении целевой таблицы
-   ```Инвалидация кэша L2 при прямых SQL обновлениях``` (риск рассинхронизации данных при native SQL) - прямые запросы `UPDATE/DELETE` в обход Hibernate не сбрасывают L2 кэш; требуется ручной вызов `sessionFactory.getCache().evict(...)`
-   ```Кэширование коллекций (@Cache на поле связи)``` (отдельное кэширование состава связей) - в L2 кэшируется список идентификаторов дочерних объектов коллекции, а не сами объекты
-   ```JCache (JSR-107) интеграция``` (стандартизированное подключение внешних систем кэширования через hibernate-jcache) - единый интерфейс конфигурации для Hazelcast, Infinispan, Ehcache 3
-   ```Статистика попаданий в кэш (Statistics.getSecondLevelCacheHitCount())``` (мониторинг эффективности кэширования и метрики Hit/Miss Ratio) - сбор телеметрии для выявления неэффективных областей кэша
