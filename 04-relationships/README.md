## Связи между сущностями
-   ```@ManyToOne (Владелец связи с внешним ключом)``` (основной строительный блок реляционных связей) - всегда содержит `@JoinColumn(name = "user_id")`; по умолчанию `fetch = EAGER`, всегда рекомендуется явно указывать `LAZY`
-   ```@OneToMany(mappedBy = "user")``` (обратная невладеющая сторона связи один-ко-многим) - атрибут `mappedBy` указывает на имя поля в целевой сущности; отсутствие `mappedBy` приведёт к созданию лишней join-таблицы
-   ```Хелпер-методы синхронизации двунаправленной связи``` (гарантия согласованности графа объектов в памяти Java) - методы `user.addOrder(order)` и `user.removeOrder(order)`, обновляющие ссылки с обеих сторон
-   ```@OneToOne``` (связь один к одному) - владельцем должен быть объект с внешним ключом; на обратной стороне обязательно `mappedBy`; для отложенной загрузки `LAZY` на обратной стороне требуется байткод-инструментирование
-   ```@ManyToMany``` (связь многие-ко-многим через промежуточную таблицу) - `@JoinTable(name = "user_roles", joinColumns = ..., inverseJoinColumns = ...)`; на практике рекомендуется заменять на две связи `@ManyToOne` через промежуточную сущность
-   ```CascadeType (PERSIST, MERGE, REMOVE, REFRESH, DETACH)``` (каскадное распространение операций жизненного цикла) - `CascadeType.ALL` удобен для композиций (Заказ → Позиции заказа); опасен при `@ManyToMany`
-   ```orphanRemoval = true``` (автоматическое удаление осиротевших дочерних записей из БД) - если сущность удалена из коллекции родителя (`user.getOrders().remove(0)`), Hibernate генерирует `DELETE` для этой записи
-   ```Использование Set вместо List для коллекций``` (предотвращение декартова произведения и MultipleBagFetchException) - `List` без индексов маппится как Bag; выборка двух Bag через JOIN FETCH бросает фатальную ошибку
-   ```@JoinColumn vs @JoinTable``` (выбор физической модели связи в таблицах) - `@JoinColumn` использует прямой внешний ключ в таблице, `@JoinTable` создает отдельную связующую таблицу
-   ```@OnDelete(action = OnDeleteAction.CASCADE)``` (генерация ON DELETE CASCADE на уровне DDL внешнего ключа СУБД) - перекладывает удаление дочерних строк на базу данных в обход генерации отдельных DELETE запросов Hibernate
