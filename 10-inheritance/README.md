## Наследование в ORM
-   ```InheritanceType.SINGLE_TABLE``` (все классы иерархии отображаются в одну единственную таблицу) - стратегия по умолчанию; максимальная производительность чтения и записи (нет JOIN); требует поддержки NULL во всех специфичных колонках подклассов
-   ```@DiscriminatorColumn & @DiscriminatorValue``` (определение колонки-дискриминатора для различения типов записей) - колонка (например `dtype varchar(31)`); значения: `ADMIN`, `CUSTOMER`, `MANAGER`
-   ```InheritanceType.JOINED``` (базовый класс и каждый подкласс имеют собственные нормализованные таблицы) - нет лишних колонок с NULL; нормальная форма БД; плата за нормализацию — сложные `JOIN` при каждом полиморфном запросе
-   ```InheritanceType.TABLE_PER_CLASS``` (каждый конкретный подкласс имеет изолированную таблицу со всеми полями родителя) - нет внешних ключей между таблицами; полиморфный запрос `FROM BaseEntity` генерирует тяжелейший `UNION ALL`
-   ```@MappedSuperclass``` (общий базовый класс для вынесения одинаковых полей без полиморфизма) - не создает таблицу; не позволяет делать полиморфные запросы `FROM BaseEntity`; стандарт для `Id`, `createdAt`, `version`
-   ```Полиморфные выборки и приведение типов (TREAT в HQL)``` (фильтрация и кастинг типов в объектных запросах) - `SELECT p FROM Payment p WHERE TREAT(p AS CreditCardPayment).cardNumber LIKE '4%'`
-   ```@DiscriminatorFormula``` (вычисление типа наследника через произвольное SQL выражение вместо статической колонки) - позволяет маппить существующие легаси схемы без выделенной колонки дискриминатора
