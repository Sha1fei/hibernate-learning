## Маппинг сущностей
-   ```@Entity``` (объявление Java-класса персистентной сущностью) - требует конструктор без аргументов (no-arg constructor); класс и не-final методы не должны быть final для генерации CGLIB/ByteBuddy прокси
-   ```@Table(name = "users")``` (явное связывание сущности с таблицей базы данных) - поддерживает указание схемы (`schema = "core"`), каталога, а также составных уникальных ограничений и индексов
-   ```@Column``` (детальная настройка отображения поля на колонку) - параметры `nullable = false`, `length = 150`, `updatable = false` (запрет обновления поля), `insertable = false`
-   ```@Enumerated(EnumType.STRING)``` (сохранение enum в виде текста вместо порядкового индекса) - защита от порчи данных при добавлении новых значений в enum (`EnumType.ORDINAL` категорически не рекомендуется)
-   ```@Temporal(TemporalType.TIMESTAMP)``` (указание типа времени для устаревших классов Date/Calendar) - не требуется для современных классов Java 8 `java.time.LocalDate`, `LocalDateTime`, `Instant`
-   ```@Lob``` (хранение больших текстовых CLOB или бинарных BLOB данных) - маппится на `text`/`oid` в PostgreSQL или `LONGTEXT`/`LONGBLOB` в MySQL
-   ```@Embedded & @Embeddable``` (встраивание класса-компонента без отдельной таблицы) - поля `@Embeddable` класса встраиваются как обычные колонки в таблицу сущности-владельца
-   ```@AttributeOverride``` (переопределение колонок встраиваемого компонента) - позволяет использовать один и тот же `@Embeddable` класс (например `Address`) несколько раз в одной сущности (`homeAddress`, `workAddress`)
-   ```@SecondaryTable``` (маппинг одной сущности сразу на две связанные таблицы) - редкие или тяжелые поля выносятся во вторую таблицу, но остаются частью одного Java-объекта
-   ```@Formula("(SELECT COUNT(*) FROM orders o WHERE o.user_id = id)")``` (вычисляемое на стороне СУБД виртуальное свойство) - read-only выражение, подставляемое прямо в SELECT запрос при загрузке сущности
-   ```@JdbcTypeCode(SqlTypes.JSON) в Hibernate 6``` (нативная поддержка JSON колонок в PostgreSQL/MySQL) - маппит сложные Java объекты или Map напрямую в JSON/JSONB колонки без написания кастомных конвертеров
-   ```@DynamicUpdate``` (генерация UPDATE запроса только с реально изменёнными колонками) - снижает сетевой трафик и объем блокировок при широких таблицах с десятками колонок
-   ```@CreationTimestamp & @UpdateTimestamp``` (автоматическое проставление времени создания и последнего изменения) - заполняются Hibernate автоматически на стороне приложения при выполнении INSERT и UPDATE
